# Стол D&D

Онлайн-стол по SRD 5.2 (CC-BY-4.0). Мастер поднимает стол на своём компьютере, игроки открывают его адрес в браузере. Отдельный сервер не нужен.

Демо-аккаунты, пароль у обоих `password123`:

| Роль | Почта |
| --- | --- |
| Мастер | `dm@table.local` |
| Игрок | `player@table.local` |

## Возможности

Пометки: **[М]** — только мастер, **[свой]** — владелец героя или мастер. Без пометки — все участники стола.

### Аккаунты и кампании

- Регистрация и вход по почте и паролю. Сессия живёт 12 часов, токен лежит в `localStorage`.
- Меню аккаунта: тёмная и светлая тема, выход.
- Список кампаний с ролью и кодом приглашения. Создатель кампании становится мастером, первая сцена «Стол» 20×14 появляется сразу.
- Вступление по коду, по полной ссылке `/join/КОД` или по кнопке «Ссылка» на столе. Вступивший получает роль игрока.
- Удаление кампании с подтверждением. Удалить может только владелец, вместе с героями, картами и бросками.
- Если стол открыт на `localhost`, на главной есть подсказка с адресами для локальной сети.

### Создание героя

Мастер из пяти шагов: класс, вид и предыстория, характеристики, навыки, имя. Хиты, КД, скорость и спасброски сервер считает сам. Заклинателям выдаются стартовые заклинания и ячейки 1 круга.

Кнопки на столе: «Новый герой». Мастер также может открыть `/campaigns/<id кампании>/characters/new`.

### Лист персонажа

Чужие листы игрок видит только для чтения.

- **Обзор:** портрет, имя, класс · подкласс · уровень, вид, КД, скорость.
  - Хиты и временные хиты: снять или добавить **[свой]**. Максимум хитов **[М]**.
  - «Новый уровень» до 20 **[свой]**: хиты, кости хитов, ячейки, ресурсы класса. На 3 уровне — выбор подкласса, на 4/8/12/16 — ASI или черта, на 19 — эпический дар.
  - Заметки героя **[свой]**.
  - Кнопки «На карту» и «Убрать с карты», удаление героя **[свой]**.
- **Проверки:** броски характеристик, навыков и спасбросков с преимуществом или помехой **[свой]**. Сами характеристики и владения правит мастер.
- **Атаки:** карточки атак с броском попадания или спасброска, индикатор ячеек заклинаний.
  - Умения класса и подкласса по уровню: бросок по формуле или включение (не путается с состояниями).
  - Ресурсы класса (ярость, очки сосредоточенности и т.п.): пипсы, трата с листа, короткий/длинный отдых.
  - Заклинания из справочника: фильтр «Мой класс / Все», поиск, группы по кругам. Можно добавить своё. Каст списывает ячейку и бросает кости.
- **Снаряжение** **[свой]**: предметы из справочника или свои (оружие, броня, щит, вещь), количество, «Надеть / Снять». КД и атаки оружием пересчитываются сами.
- Вдохновение, истощение 0–10 (−2 к броскам d20 за уровень), спасброски от смерти, шесть состояний.
- Короткий отдых тратит кость хитов. Длинный восстанавливает хиты, кости хитов и ячейки и снимает уровень истощения.

### Карта и сцены

- Несколько сцен **[М]**: создать, удалить, выбрать активную. Игроки видят активную.
- Загрузка карты PNG, JPG, WebP или GIF **[М]**.
- Настройка сетки **[М]**: пресеты размеров, шаг, смещение, квадраты или гексы, цвет и прозрачность, масштаб карты и «Подогнать под сетку».
- Инструменты: ход, линейка (5 футов на клетку), шар, конус и линия.
- Зум кнопками и колесом, «Вписать». Карту двигают мышью по пустому месту, средней или правой кнопкой, или с зажатым пробелом.
- Фишки прилипают к клеткам. Портрет героя становится картинкой фишки, обводка краснеет при низких хитах.
- Туман войны **[М]**: прямоугольники, «Туман на всю карту», «Сбросить». Мобов под туманом игроки не видят.
- Скрытые фишки **[М]**: игроки их не получают ни на карте, ни в бою.
- Заметки мастера к каждой сцене **[М]**. Игрокам они не отправляются.

### Мобы (всё [М])

- «Добавить моба»: монстры из справочника с КР, хитами и КД. Можно поставить от 1 до 12 копий, они нумеруются сами: «Гоблин 1», «Гоблин 2».
- Свой моб: характеристики и атака. Ставится на карту или сохраняется шаблоном кампании.
- Карточка моба: имя, КД, хиты, скорость, портрет, скрытие. Проверки, спасброски, атаки и снаряжение.

### Бой

- «Начать», «Дальше», «Конец» **[М]**. Инициатива бросается всем фишкам сцены, раунды считаются.
- Полоса инициативы видна всем. Клик по участнику центрирует карту и открывает его лист.
- Текущий ход: выбор цели и «Ударить». Сервер бросает попадание против КД (20 — крит, 1 — промах) и списывает урон, сначала с временных хитов.

### Кости

- Лоток: формула до 40 костей d4–d100, модификатор, быстрые кнопки, преимущество и помеха.
- Все броски делает сервер и сохраняет в истории. Новый бросок всплывает у всех, натуральные 1 и 20 подсвечены.

### Синхронизация

Любое изменение сразу видно всем: сервер рассылает по WebSocket снимок стола, собранный под роль каждого. После обрыва клиент переподключается сам.

## Игровой вечер

Нужны Docker и свободный порт `8080`.

```powershell
docker compose up --build
```

Стол: [http://localhost:8080](http://localhost:8080).

Postgres слушает только `127.0.0.1:5433`. Из локальной сети к базе не подключиться. При первом старте API сам применяет миграции и создаёт демо-аккаунты.

Остановить: `docker compose down`. Данные кампаний остаются в томе Postgres.

## Разработка

Нужен [Bun](https://bun.sh). Postgres тот же, что в compose.

```powershell
docker compose up -d postgres
bun install
bun run db:migrate
bun run db:seed
```

Два терминала:

```powershell
bun run dev:api
bun run dev:web
```

Интерфейс: [http://localhost:4200](http://localhost:4200). API: `http://localhost:3000`. Vite проксирует `/api` и WebSocket.

### Команды

| Команда | Что делает |
| --- | --- |
| `bun run dev:api` | API на `:3000` (`nx serve api`). Перезапускается при правке файлов. При старте применяет миграции, обновляет справочник в базе и создаёт демо-аккаунты. |
| `bun run dev:web` | Интерфейс на `:4200` (`nx serve web`, Vite). Проксирует `/api` и WebSocket на `:3000`. |
| `bun run build` | Сборка всех проектов: API в `dist/apps/api`, интерфейс в `dist/apps/web`. |
| `bun run typecheck` | `tsc --noEmit` для `api`, `web` и `shared`. |
| `bun run lint` | ESLint по всему репозиторию. |
| `bun run lint:fix` | ESLint с автоисправлением. |
| `bun run db:generate` | Новая миграция Drizzle из `apps/api/src/db/schema.ts` в `apps/api/drizzle`. Запускать после правки схемы. |
| `bun run db:migrate` | Применяет миграции к базе из `DATABASE_URL`. |
| `bun run db:seed` | Записывает справочник в таблицу `srd_entries` и создаёт демо-аккаунты. То же делает старт API. |
| `bun run srd:import` | Скачивает справочник заново и перезаписывает `packages/shared/src/srd-2024-*.json`. Нужен интернет. |
| `bun run srd:import:classes` | Обновляет только классы и подклассы с `next.dnd.su`, не трогая остальной справочник. Нужен интернет. |
| `powershell -File scripts/print-join-url.ps1` | Печатает адрес стола для локальной сети и Tailscale. |

Отдельный проект: `bunx nx run api:typecheck`, `bunx nx run web:build` и так далее.

### Обновить справочник

```powershell
bun run srd:import
```

Скрипт берёт из Open5e заклинания, оружие, доспехи, монстров, классы, подклассы и черты SRD 2024. Названия, школы магии, типы урона и свойства оружия переводит словарями, атаки монстров разбирает из их действий. Списки навыков класса читает из CORE_TRAITS. В конце печатает число записей и названия, оставшиеся без перевода. Словари лежат в `scripts/import-srd-catalog.ts` и `scripts/import-srd-heroes.ts`.

Классы и подклассы поверх этого перезаписывает `scripts/import-dndsu-classes.ts`: он разбирает страницы классов на `next.dnd.su` и даёт русские тексты умений, 12 классов PHB 2024 и все 48 подклассов, ключевые атрибуты класса и таблицу умений по уровням. Соответствие подклассов сайта записям каталога задано таблицей `subclassIdByCode`, колонок таблицы умений — `tableIdByColumn`. Характеристика заклинаний, защита без доспехов, мастерство оружия и список заклинаний на страницах не размечены, поэтому берутся из предыдущего JSON.

После импорта перезапусти API или выполни `bun run db:seed`. Таблица `srd_entries` станет совпадать с JSON, лишние записи удалятся.

### Переменные окружения

Пример — `.env.example`. Без файла API берёт значения по умолчанию, их хватает для локальной разработки.

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `DATABASE_URL` | `postgresql://dnd:dnd@localhost:5433/dnd` | Postgres |
| `JWT_SECRET` | `dev-secret-change-in-production` | Подпись токенов сессии |
| `PORT` | `3000` | Порт API |
| `CORS_ORIGIN` | `http://localhost:4200` | Откуда разрешены запросы к API |
| `UPLOAD_DIR` | `./data/uploads` | Карты, портреты и картинки фишек |

### Устройство

- `apps/api`: Elysia, Drizzle, Postgres. REST и WebSocket `/live/:campaignId`.
- `apps/web`: React, Mantine, Virentia, Konva для карты.
- `packages/shared`: правила, Zod-схемы, справочник SRD. Общие для API и интерфейса.

В Docker интерфейс отдаёт nginx на `:8080` и проксирует `/api` и WebSocket в API.

## Мастер и игрок с одного компьютера

Две вкладки обычного окна — это **один** аккаунт. Токен сессии лежит в `localStorage` и общий для всех вкладок этого профиля. Вторая вкладка не станет игроком, пока в первой сидит мастер.

Нужны два отдельных хранилища. Подойдёт любое:

- обычное окно Chrome и окно инкогнито;
- Chrome и Firefox (или Edge);
- два профиля одного браузера.

Оба окна открывают **один и тот же** адрес: `http://localhost:8080` в игровом режиме или `http://localhost:4200` в разработке. Предупреждение про localhost относится к друзьям с других компьютеров. На этой машине localhost работает в обоих окнах.

1. Окно мастера. Войти как `dm@table.local`. Создать кампанию или открыть существующую.
2. На столе скопировать строку «Приглашение». Она выглядит так: `http://localhost:8080/join/КОД`.
3. Окно игрока. Сначала открыть `http://localhost:8080/login` и войти как `player@table.local`. Если открыть приглашение до входа, сайт уведёт на логин и забудет код.
4. Уже будучи игроком, вставить ссылку приглашения в адресную строку этого же окна. Стол откроется с ролью «Игрок».

Проверка, что роли разные:

- бросок костей и сдвиг фишки видны в обоих окнах;
- скрытая фишка и заметки мастера есть только у мастера;
- у игрока нет кнопок «Начать» бой, «На карту» и корзины удаления.

## Друзья в сети

Ссылка с `localhost` с другого компьютера не откроется. На машине мастера:

```powershell
powershell -File scripts/print-join-url.ps1
```

Скрипт печатает `http://<lan-ip>:8080`. Этот адрес подставляют вместо localhost, код приглашения тот же: `http://<lan-ip>:8080/join/КОД`. С другой Wi-Fi этот адрес не откроется.

Один раз разрешить входящий TCP `8080` в брандмауэре Windows для частной сети.

Пока `docker compose` запущен и компьютер мастера включён, стол доступен. Выключили машину — сессия пропала, данные в томе Postgres остались.

## Друзья в другой сети (Tailscale)

Туннель в стол не встроен. [Tailscale](https://tailscale.com/download) даёт компьютеру мастера адрес вида `100.x.y.z`. Его видят только люди из той же сети Tailscale. Белый IP и проброс порта на роутере не нужны.

Так делают один раз:

1. Мастер ставит Tailscale для Windows и входит в свой аккаунт. В трее статус Connected. Выход из трея обрывает доступ, даже если Docker ещё запущен.
2. В [админке](https://login.tailscale.com/admin/users) мастер приглашает каждого игрока. Игрок принимает приглашение и ставит Tailscale на свой компьютер (Windows, macOS, Linux, телефон). Общий логин на всех не нужен. Игрок тоже остаётся Connected на время игры.
3. На машине мастера открыть входящий TCP `8080` на всех профилях брандмауэра. Адаптер Tailscale Windows часто помечает как публичную сеть, правило «только частная сеть» его не пускает:

```powershell
New-NetFirewallRule -DisplayName "D&D table 8080" -Direction Inbound -Protocol TCP -LocalPort 8080 -Action Allow -Profile Any
```

Каждый вечер, когда игроки не в домашней Wi-Fi мастера:

1. У мастера Tailscale Connected, затем `docker compose up --build`. Tailscale стоит на Windows, не внутри контейнера.
2. Узнать адрес:

```powershell
powershell -File scripts/print-join-url.ps1
```

Игрокам отдают строку `Tailscale: http://100.x.y.z:8080`. Строку «Та же сеть» из другой сети не открыть.

3. В приглашении со стола заменить `localhost` на этот адрес: `http://100.x.y.z:8080/join/КОД`.
4. Игрок с уже включённым Tailscale сначала открывает `http://100.x.y.z:8080/login` и входит своим аккаунтом. Потом вставляет приглашение. Если открыть приглашение до входа, сайт уведёт на логин и забудет код. У каждого игрока свой аккаунт: общий `player@table.local` — это один человек.

Проверка с компьютера игрока: в списке Tailscale видна машина мастера, страница `http://100.x.y.z:8080` открывается. `localhost` у игрока — его собственный компьютер, не стол.

Если короткое имя машины не резолвится, играть по `100.x.y.z`. IP из `tailscale ip -4` работает и без MagicDNS.

Funnel и Serve не включать. Они публикуют порт в интернет. Для вечера хватает адреса `100.x` внутри tailnet.
