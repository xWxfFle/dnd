# Стол D&D

Онлайн-стол по SRD 5.2 (CC-BY-4.0). Мастер поднимает стол на своём компьютере, игроки открывают его адрес в браузере. Отдельный сервер не нужен.

Демо-аккаунты, пароль у обоих `password123`:

| Роль | Почта |
| --- | --- |
| Мастер | `dm@table.local` |
| Игрок | `player@table.local` |

## Игровой вечер

Нужны Docker и свободный порт `8080`.

```powershell
docker compose up --build
```

Стол: [http://localhost:8080](http://localhost:8080).

Postgres слушает только `127.0.0.1:5433`. Из локальной сети к базе не подключиться. При первом старте API сам применяет миграции и создаёт демо-аккаунты.

Остановить: `docker compose down`. Данные кампаний остаются в томе Postgres.

## Разработка

Нужен [Bun](https://bun.sh). Postgres тот же, что в compose.

```powershell
docker compose up -d postgres
bun install
bun run db:migrate
bun run db:seed
```

Два терминала:

```powershell
bun run dev:api
bun run dev:web
```

Интерфейс: [http://localhost:4200](http://localhost:4200). API: `http://localhost:3000`. Vite проксирует `/api` и WebSocket.

Проверки: `bun run lint`, `bun run typecheck`, `bun run build`.

## Мастер и игрок с одного компьютера

Две вкладки обычного окна — это **один** аккаунт. Токен сессии лежит в `localStorage` и общий для всех вкладок этого профиля. Вторая вкладка не станет игроком, пока в первой сидит мастер.

Нужны два отдельных хранилища. Подойдёт любое:

- обычное окно Chrome и окно инкогнито;
- Chrome и Firefox (или Edge);
- два профиля одного браузера.

Оба окна открывают **один и тот же** адрес: `http://localhost:8080` в игровом режиме или `http://localhost:4200` в разработке. Предупреждение про localhost относится к друзьям с других компьютеров. На этой машине localhost работает в обоих окнах.

1. Окно мастера. Войти как `dm@table.local`. Создать кампанию или открыть существующую.
2. На столе скопировать строку «Приглашение». Она выглядит так: `http://localhost:8080/join/КОД`.
3. Окно игрока. Сначала открыть `http://localhost:8080/login` и войти как `player@table.local`. Если открыть приглашение до входа, сайт уведёт на логин и забудет код.
4. Уже будучи игроком, вставить ссылку приглашения в адресную строку этого же окна. Стол откроется с ролью «Игрок».

Проверка, что роли разные:

- бросок костей и сдвиг фишки видны в обоих окнах;
- скрытая фишка и заметки мастера есть только у мастера;
- у игрока нет кнопок «Начать» бой, «На карту» и корзины удаления.

## Друзья в сети

Ссылка с `localhost` с другого компьютера не откроется. На машине мастера:

```powershell
powershell -File scripts/print-join-url.ps1
```

Скрипт печатает `http://<lan-ip>:8080`. Этот адрес подставляют вместо localhost, код приглашения тот же: `http://<lan-ip>:8080/join/КОД`. С другой Wi-Fi этот адрес не откроется.

Один раз разрешить входящий TCP `8080` в брандмауэре Windows для частной сети.

Пока `docker compose` запущен и компьютер мастера включён, стол доступен. Выключили машину — сессия пропала, данные в томе Postgres остались.

## Друзья в другой сети (Tailscale)

Туннель в стол не встроен. [Tailscale](https://tailscale.com/download) даёт компьютеру мастера адрес вида `100.x.y.z`. Его видят только люди из той же сети Tailscale. Белый IP и проброс порта на роутере не нужны.

Так делают один раз:

1. Мастер ставит Tailscale для Windows и входит в свой аккаунт. В трее статус Connected. Выход из трея обрывает доступ, даже если Docker ещё запущен.
2. В [админке](https://login.tailscale.com/admin/users) мастер приглашает каждого игрока. Игрок принимает приглашение и ставит Tailscale на свой компьютер (Windows, macOS, Linux, телефон). Общий логин на всех не нужен. Игрок тоже остаётся Connected на время игры.
3. На машине мастера открыть входящий TCP `8080` на всех профилях брандмауэра. Адаптер Tailscale Windows часто помечает как публичную сеть, правило «только частная сеть» его не пускает:

```powershell
New-NetFirewallRule -DisplayName "D&D table 8080" -Direction Inbound -Protocol TCP -LocalPort 8080 -Action Allow -Profile Any
```

Каждый вечер, когда игроки не в домашней Wi-Fi мастера:

1. У мастера Tailscale Connected, затем `docker compose up --build`. Tailscale стоит на Windows, не внутри контейнера.
2. Узнать адрес:

```powershell
powershell -File scripts/print-join-url.ps1
```

Игрокам отдают строку `Tailscale: http://100.x.y.z:8080`. Строку «Та же сеть» из другой сети не открыть.

3. В приглашении со стола заменить `localhost` на этот адрес: `http://100.x.y.z:8080/join/КОД`.
4. Игрок с уже включённым Tailscale сначала открывает `http://100.x.y.z:8080/login` и входит своим аккаунтом. Потом вставляет приглашение. Если открыть приглашение до входа, сайт уведёт на логин и забудет код. У каждого игрока свой аккаунт: общий `player@table.local` — это один человек.

Проверка с компьютера игрока: в списке Tailscale видна машина мастера, страница `http://100.x.y.z:8080` открывается. `localhost` у игрока — его собственный компьютер, не стол.

Если короткое имя машины не резолвится, играть по `100.x.y.z`. IP из `tailscale ip -4` работает и без MagicDNS.

Funnel и Serve не включать. Они публикуют порт в интернет. Для вечера хватает адреса `100.x` внутри tailnet.
